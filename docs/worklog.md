# 작업 기록

무엇을 왜 바꿨는지 남기는 곳. **최신이 맨 위.**

작업을 끝낼 때마다 항목 하나를 추가한다. 형식은 아래와 같다.

```markdown
### 제목 — 한 줄로 무엇을 했는지

**왜**: 근거 (설계서 절 번호, 요소 번호, 문서 이름). 추측이면 추측이라고 쓴다.
**바꾼 것**: 파일과 요점
**남은 것**: 이어서 할 일이나 확인 못 한 것. 없으면 생략
```

- 코드를 고치지 않은 결정(화풍 확정, 계약 합의 등)도 남긴다. 나중에 "왜 이렇게 했지"가 여기서 풀린다.
- 실패하거나 되돌린 것도 남긴다. 같은 함정을 두 번 밟지 않으려는 기록이다.
- 할 일은 여기 쓰지 않는다. `docs/backlog.md`로 간다.

### 네이버 로그인을 뺌 — 보류

**왜**: 사용자 「네이버는 할 지는 모르겠는데 일단 지워놔줘」.
**바꾼 것**: 프론트는 제공자 목록·인가 주소·client id·버튼 리소스(`public/brand/naver/`)를,
백엔드(`feat/social-login` `6cbe4cd`)는 제공자·설정·테스트를 뺐다. 네이버 때문에만 백엔드로 보내던
`state` 도 함께 뺐다 (프론트에서 확인은 계속한다). 다시 넣으려면 두 저장소의 해당 커밋을 되돌린다.
**확인**: 프론트 `typecheck`, 백엔드 테스트 20개·`ruff` 통과.

### 소셜 로그인을 카카오·네이버·구글로 넓히고 백엔드 API 를 만들어 push

**왜**: 사용자 질문 「구글이랑 네이버 인증도 가능한가?」와 지시 「백엔드 영역은 브랜치 새로 만들어서
푸쉬」. 셋 다 인가 코드 방식이라 제공자만 바꿔 끼우는 구조로 한 번에 붙였다.
**백엔드** (`drawtale-backend` `feat/social-login`, dev 에서 분기, 커밋 `8b93ad3`):
`POST /api/v1/auth/{kakao|naver|google}`, `GET /api/v1/auth/me`, users·social_accounts·auth_tokens
migration(autogenerate 후 로컬 Postgres 에서 upgrade → downgrade → upgrade, `alembic check` 차이 없음),
토큰은 SHA-256 만 저장, 처음 온 사람은 `409 SIGNUP_REQUIRED`, 키 없는 제공자는 503. 테스트 8개 추가
(제공자 HTTP 는 MockTransport) — 기존 13개와 함께 21개 통과, `ruff check` 통과. 계약서 2-7·2-8, README.
**프론트**: 제공자 셋, 인가 주소(구글만 scope `openid`), 백엔드에 `state` 도 보냄(네이버 필요),
`SocialButtons` 로 세 버튼을 같은 폭 260px 로. 버튼은 세 곳 모두 공식 리소스를 고치지 않고 넣었다 —
카카오는 폭을 맞추려고 large → medium, 네이버 KR narrow H56, 구글 Light Square(영어뿐).
**확인**: 목 모드 브라우저 — 네이버 처음 로그인 → S-16(「네이버 계정으로」 안내, 버튼 잠김) → 동의 →
가입 → S-01, 구글 가입 화면에서 바로 가입 → S-01. `typecheck` 통과.
**확인 못 한 것**: 실제 제공자 키로 돌려 보지 못했다(콘솔 등록 전). 프론트 ↔ 백엔드 브랜치를 붙여서도
돌리지 않았다 — 모양은 백엔드 테스트와 계약서로만 맞췄다.

### 실제 모델 붙이기 — 직접 빌드에서 팀원 `drawtale-ai` 로 갈아탐

**왜**: `docs/animated-drawings-local.md` ④⑤ 단계.
**한 것**: Meta 원본 TorchServe Dockerfile 이 bullseye 저장소 404 로 빌드되지 않아
`archive.debian.org` 로 돌린 사본을 만들어 빌드(32.9GB)하고, 스텁의 분석 부분만 TorchServe
를 부르는 어댑터를 만들었다. CPU 로 장당 2.5~3초, crop → 원본 좌표 변환이 그림 위에 정확히
겹쳤다. 합성한 `head` 는 연장 1.0 이 너무 높았고, garlic 그림처럼 코가 어깨보다 낮게 잡히면
머리가 몸통 안으로 들어갔다(그때 neck 점수 0.28).
**되돌린 것**: 팀원 `drawtale-ai` 가 같은 문제를 풀어 두었고(snapshot 저장소, CPU 전용
PyTorch 로 5.85GB, 작업자 1개) 백엔드가 그것을 부르므로 갈아탔다. 같은 Meta 가중치라
좌표 차이는 이미지 크기의 1% 미만. 내 Dockerfile·어댑터·32.9GB 이미지는 지웠다.

### 스텁에 붙여 S-01~S-11 전 구간을 실서버 모드로 돌렸다

**왜**: 스텁을 만들었으니 `VITE_ENGINE=finetuned` 로 실제 화면을 끝까지 돌려서
실서버 분기가 정말 도는지 본다. `backlog.md` P1-5 항목이다.

**결과**: **전 구간이 통과했다.** S-01 → S-02 → S-03(업로드) → S-04(SSE) → S-05 →
S-06(관절 목록) → S-05 → S-07(장소·문제·행동·결과) → S-08 → S-09(장면 4개) →
S-10(순서 맞추기) → S-11. 스텁 stderr 는 비어 있다.

- 좌표가 샘플 그림의 뼈대와 맞아서 S-05 에서 캐릭터가 제자리에 섰다
- `right_elbow` score 0.34 가 S-05 의 「어른에게 도움 받기」와 S-06 의 빨간 점으로
  제대로 이어졌다. `confidence` 0.82 는 경계(0.6) 위라 그것 때문이 아니다 —
  **score 기반 유도가 따로 동작하는 것을 확인했다**
- Level 1 이라 선택지가 2개로 왔다. `GET /api/steps?level=1` → 2개, 서버가 개수를
  맞춰 보내는 계약이 그대로 동작한다
- `POST /api/stories/{id}/activity` 가 `tries=1 done=False` → `tries=2 done=True`
  로 두 번 찍혔다

**바꾼 것**: `vite.config.ts` — 프록시 대상을 `localhost` 에서 `127.0.0.1` 로.
아래 앞 항목의 1번(요청마다 2초)을 고친 것이다. 이유를 주석으로 남겼다.

**새로 나온 것 네 개.** 앞 항목의 여섯 개에 더해 `backlog.md` P0-0 표에 g~j 로 넣었다.

1. **`patchKeypoints` 를 아무 데서도 부르지 않는다.** 계약에도 있고 `api/index.ts`
   에 구현도 돼 있는데 호출부가 없다. `S06Joints.tsx` 40행의 「다 했어요」는
   세션만 고치고 이동한다. **어른이 맞춘 관절이 서버로 가지 않는다**
2. **`audioUrl` 을 아무 데서도 읽지 않는다.** `<audio>` 도 `new Audio` 도 없다.
   S-09 는 항상 브라우저 TTS 다. **TTS 업체를 고르는 일(`open-decisions.md` 6번)이
   지금은 소비처가 없는 필드를 위한 결정이다** → 14번으로 올렸다
3. **개발 모드에서 같은 요청이 두 번 나간다.** StrictMode 가 effect 를 두 번 돌리는데
   cleanup 의 `abort()` 는 이미 서버에 도착한 요청을 되돌리지 못한다. 스텁 로그에
   `POST /api/characters` 2회, `POST /api/stories` 2회(이야기 두 편 생성)가 찍혔다.
   프로덕션에는 없는 일이지만 **개발·통합 테스트 내내 AI 비용이 두 배다**
4. **`shrink()` 가 작은 그림은 원본 그대로 보낸다.** `lib.ts` 21행이 긴 변 1600px
   이하이고 2MB 미만이면 재인코딩 없이 빠져나간다. 계약 1절의 「JPEG 로 재인코딩한다.
   원본은 보내지 않는다」와 다르다. 스텁이 `⚠ image/png — 계약은 JPEG` 를 찍어서
   드러났다. **백엔드는 PNG·WebP·HEIC 디코더가 필요하다**

**확인 못 한 것**: S-06 의 관절 끌기는 자동화로 재현하지 못했다(합성 포인터 이벤트).
사람 손으로 한 번 확인해야 한다. `audioUrl` 에 실제 wav 를 주는 경로도 화면에서는
확인하지 않았다 — 위 2번 때문에 지금은 읽지 않으므로 확인할 것이 없다.

**남긴 상태**: `.env` 가 `VITE_ENGINE=finetuned` 다. 스텁 없이 열면 화면이 멈춘다.
목으로 돌아가려면 `mock` 으로 되돌린다.

### 장면 배경을 언제 만들지 — 쟁점 정리

**왜**: 팀원이 미리 만들지 말고 아이가 이야기를 만들 때 생성하자고 제안했다.

  우려했으나, 레퍼런스를 참조시키면 그 문제는 상당 부분 해결된다

- **대기 시간은 풀린다.** 아이가 S-07 에서 고르는 동안 뒤에서 생성하면 된다.
  통합 정리 문서가 애니메이션 렌더에 대해 이미 같은 패턴을 제안했다
- **남는 것은 비용과 검수.** 8주 총액이 A안 352,750원, C안 385,750원,

OpenAI 자체 필터는 있다. 다만 그것이 막는 것은 성적·폭력적·혐오 콘텐츠이고,

통과한다. 문장과 달리 **우리가 기준을 정해 부를 수 있는 판정 API가 없다**는 것이

**확인**: 세 레벨을 목 엔진으로 다시 봤다. Level 2·3은 회귀 없이 그대로다.

**남은 것**: Level 1 카드는 아래 40%가 여전히 빈다. 근본 원인은 선택지가 둘뿐이라
카드가 화면 높이를 거의 다 쓴다는 것이다. 터치 타깃이 커서 나쁘지 않지만,
카드 최대 크기를 제한할지는 실기기에서 보고 정한다.

### S-07 선택지 카드가 좌우로 벌어지던 것 수정

**왜**: 열이 `1fr`이라 셀이 화면 폭을 꽉 나눠 갖는데, 카드 폭은 `aspect-ratio`로
**높이에서 파생된다.** 그래서 카드가 셀보다 훨씬 좁고, 셀 가운데에 놓이면
카드 사이가 크게 벌어졌다.

**바꾼 것**: `src/styles/ui.css` — 열을 `1fr`에서 `auto`로 바꾸고
`justify-items: center` 대신 `justify-content: center`를 썼다.
열이 카드 폭을 따라가므로 카드들이 `gap`만큼만 떨어져 가운데 모인다.
행은 `minmax(0, 1fr)` 그대로 둔다 — 그게 없으면 카드가 화면을 넘긴다.

**확인**: 세 레벨을 모두 목 엔진으로 봤다.

| 레벨 | 선택지 | 배치 |
|---|---|---|
| 1 | 2개 | 2열 1행, 아이콘 160px, 라벨 없음 |
| 2 | 4개 | 2열 2행 |
| 3 | 6개 | 3열 2행, 아이콘 104px, 라벨 있음 |

**남은 것**: Level 1은 라벨이 없는데 `.choice`가 `justify-content: flex-end`라
아이콘이 카드 아래쪽에 치우친다. 카드 위쪽 절반이 빈다.

### 비회원 세션이 새로고침에 날아가던 것 수정

**왜**: `App.tsx`의 `pagehide` 핸들러가 비회원일 때 `resetAll()` +
`sessionStorage.clear()`를 했다. 그런데 **`pagehide`는 탭을 닫을 때만이 아니라
페이지를 떠날 때마다 발생한다** — 새로고침, 주소 직접 입력, 외부 링크 전부.
아이가 실수로 새로고침하면 만들던 이야기가 통째로 사라졌다.

설계서 11.1이 요구하는 「탭을 닫으면 함께 사라진다」는 **`sessionStorage` 자체가
보장한다.** 브라우저가 탭과 함께 지운다. 메모리 상태와 objectURL 도 페이지가
사라질 때 같이 해제된다. 핸들러가 할 일이 없었다.

**바꾼 것**: `src/App.tsx` — 핸들러 삭제. 쓰이지 않게 된 `useSession` import 와
`resetAll` 도 함께 정리했다. 왜 없는지 주석으로 남겼다 — 없으면 누가 다시 넣는다.

**확인**: 목 엔진으로 비회원 이야기 한 편을 만들고 실제로 검증했다.

| 조건 | 결과 |
|---|---|
| 새로고침 | `mode=guest`, 이야기 1편, 제목, 경로까지 유지 |
| 새 탭에서 열기 | `mode=null` → `/welcome`, 이야기 0편 |
| 체험 횟수 | `trial=1` 로 기기에 남음 (localStorage, 의도대로) |

**앞으로**: 비회원 세션을 끊어야 할 때는 `store/auth.ts`의 `logout()`을 쓴다.
`pagehide`·`beforeunload`에 저장소를 비우는 코드를 넣지 않는다.

### S-07 선택지 카드가 화면을 넘던 것 수정

**왜**: 4개일 때 2×2로 바꾸고 나서 카드가 화면 밖으로 밀려, 스크롤해야 선택지가
보였다. 설계서 2장 「한 화면 한 질문」이 깨진다.

원인은 `.choice`의 `aspect-ratio: 3 / 4`였다. 2열이면 카드 폭이 약 620px가 되고
높이가 827px로 계산된다. 2행이면 1650px라 어떤 화면에도 들어가지 않는다.
**폭 기준으로 높이를 정하는 비율이 2행 그리드와 맞지 않는다.**

**바꾼 것**: `src/styles/ui.css`
- `.choices`에 `grid-auto-rows: minmax(0, 1fr)` — 행이 남은 높이를 나눠 갖는다
- `.choice`를 `height: 100%; width: auto`로 — 높이 기준으로 폭을 잡는다
- `justify-items: center`로 카드를 셀 가운데에

**남은 것**: 카드가 셀 안에서 가운데 정렬되다 보니 2열일 때 좌우로 벌어져 보인다.
동작에는 문제가 없고 미관 문제다.

### 목 엔진에 그림 경로 연결

**왜**: 아이콘·배경 결정이 났으므로(설계서 9장 7·8번) 파일이 들어올 자리를 미리
뚫어 둔다. 백엔드가 없는 개발·시연 구간은 프론트가 파일을 직접 참조해야 한다
(`docs/art-direction.md` 7절).

경로는 `/icons/{kind}/{id}.png`다. id가 kind 안에서만 유일해서 폴더로 갈랐다 —
장소에 「해」를 넣으면 결과의 `sun`과 파일 이름이 부딪힌다
(`docs/id-conventions.md` 1절).

**바꾼 것**
- `api/mock/fixtures.ts` — 선택지 데이터를 `RAW` 튜플 배열로 바꿔 kind가 한 곳에만
  오게 했다. `USE_REAL_ICONS`·`USE_REAL_BG` 스위치와 `bgUrl()` 추가

  값을 받아도 화면에서 쓰지 않아 S-09가 흰 박스였다

스위치는 아직 둘 다 `false`다. 그림 54장이 들어오면 `true`로 바꾼다.
그때까지는 임시 이모지로 돈다.

### 아이콘·배경 화풍 확정

**왜**: 설계서 9장이 남긴 7번(선택지 아이콘, 2주차)·8번(장면 배경, 3주차)을 닫았다.
화면이 밋밋한 원인이 디자인 원칙이 아니라 **넣을 것이 없어서**라고 판단했다 —
아이콘은 이모지, 삽화는 자리만 채운 SVG, 배경은 전부 `null`이었다.

결정: 아이콘 24장은 **장소만 사물, 문제·행동·결과는 실루엣 인물**.
배경은 **장소 6 × 장면 분위기 4 = 24장**. 삽화 6장.

**바꾼 것**: `docs/art-direction.md` 신규. 스타일 앵커 한 문단, 종류별 프롬프트 틀,
대상 54개 전체 목록, 생성 순서, 검수 기준.
`docs/open-decisions.md`와 `docs/backlog.md`에 결정 반영.

비용은 $2.57이고 탐색을 5배로 잡아도 $13이다. 통합 정리 문서가 A안에 잡아 둔
이미지 생성 41,000원 안에 들어간다.

**남은 것**: 아직 한 장도 뽑지 않았다. Mini로 3장 먼저 뽑아 화풍을 확정한 뒤
나머지를 간다. S-02 예시 사진 3장은 여기서 만들지 않는다 — 실제 모델이 성공·실패하는
조건을 보여주는 기능이라 1주차 PoC 결과에서 골라야 한다.

### 지원 수준 점검과 수정 세 건

**왜**: Level 2 한 벌만 돌려본 상태였다. 1과 3은 아무도 확인하지 않았다.

### S-04·S-08이 개발 모드에서 영구히 멈추던 버그

**왜**: `useRef(new AbortController())`는 인스턴스를 하나만 만드는데,
`React.StrictMode`는 개발 모드에서 effect를 마운트 → 언마운트 → 재마운트로 두 번
돌린다. 첫 cleanup의 `ctrl.abort()`가 그 하나뿐인 컨트롤러를 끊어서, 두 번째 실행이
**이미 끊긴 signal**로 분석을 시작한다. `AbortError`를 `.catch`가 조용히 무시하므로
「친구를 만들고 있어요」에서 아무 일도 일어나지 않는다.

**프로덕션 빌드에는 나타나지 않아 `npm run build`로는 잡히지 않는다.**

**바꾼 것**: `S04Analyzing.tsx`, `S08Generating.tsx` — 컨트롤러를 effect 안에서 만든다.
`stop()`은 `abort.current?.abort()`로.

**앞으로**: effect 안에서 쓰는 `AbortController`는 effect 안에서 만든다.
