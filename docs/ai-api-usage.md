# AI API 활용 정리 — GPT · Claude · 음성 (2026-10-27 기준)

보고서용 정리. **서비스 안에서 AI API 를 어떻게 쓰는지와 그것을 정하려고 한 시험**만 모았다.
코딩 에이전트(Claude Code 등)로 코드를 짠 것은 넣지 않았다.
근거 파일은 줄 끝 괄호에 적었다 (`backend` = drawtale-backend dev, `exp` = hankan-story/experiments).

## 1. 이야기 글 만들기 — OpenAI GPT

아이가 S-07 에서 고른 카드 네 장(장소 · 문제 · 행동 · 결과)과 말로 덧붙인 말을 받아 이야기를 쓴다.
**원칙: 이야기의 주인은 아이다** — AI 는 아이가 고른 것을 문장으로 잇기만 하고, 고르지 않은 큰 사건을 만들지 않는다.

**네 문장 판** (`backend app/services/story_writer.py`)
- **Claude Opus 5.5 (effort low, 10/28 사용자 「전부 클로드로」)**, 실패하면 그 시도만 `gpt-4o-mini`(temperature 0.8, 최대 300토큰). 「~어요」 말투, 주인공 「나」. 고르지 않은 인물을 데려오지 않는다.
- 「캐릭터 목소리」 판이면 대사 1~2개를 넣고 말하는 사람 · 감정을 붙인다 (TTS 가 인물별 목소리로 읽음).

**8쪽 그림책 판** (`backend app/services/book.py`, 10/12)
- `gpt-5.4-mini`, JSON 으로만 답하게 함. 쪽마다 단계 · 캐릭터 동작 · 글 · 아이 말 · 대사 줄.
- `gpt-4o-mini` 에서 바꾼 이유: 카드 뜻을 뒤집고(「도와줬어요」 → 도움을 요청) 쪽 배치를 어겼다.
- 지시문 핵심: 쪽 배치 고정(장소 1 · 문제 2 · 행동 2 · 결과 3), 단계 첫 쪽에 카드 글자를 거의 그대로, 아이 말은 뜻을 바꾸지 않고, 아이 생각이 앞뒤가 안 맞아도 살린다(우주에 비가 와도), 위험한 행동은 마법 · 상상으로 바꾼다.
- **검사기 + 다시 쓰기**: 형식 오류 · 검열 · 검사기(카드가 그 단계 쪽에 있나, 쪽 수 등)에 걸리면 세 번까지 다시 쓴다. 끝내 안 되면 틀 문장 그림책(fallback)으로 — **API 가 없어도 이야기는 나온다**.

**새로 넣는 중 (로컬, 회의 전)**: S-07 에서 「누가 함께 나올까요?」 · 「기분이 어땠을까요?」 카드를 더 받아 지시문에 넣는다 — 카드 네 장으로 8쪽을 쓰면 AI 가 지어내는 양이 많아서 (`docs/open-decisions.md` 0-11).

## 2. 대본 모델 비교 — Claude Opus 5.5 vs GPT (10/27)

새 방향(배경 그림을 실시간으로 만들고 배경 안에 다른 인물도 그림)에는 대본과 함께 **쪽마다 배경 지시문 · 나오는 인물 · 말풍선 계획**이 필요하다. 어느 모델이 안정적인지 쟀다 (`exp storybook-script/compare_1027/`).

- 방법: 백엔드 실제 지시문 · 검사기를 그대로, 카드 조합 30개(아이 말 · 위험한 말 섞음), 서비스처럼 세 번까지 다시 쓰기.

| | Claude Opus 5.5 | gpt-5.4-mini (지금 서비스) |
|---|---|---|
| 대본 최종 통과 | **30/30** | 29/30 (한 편은 검열에 세 번 걸려 실패) |
| 장면 계획 통과 | **30/30** | 20/30 (행동 · 결과 쪽에 주인공 빠짐 등) |
| 위험한 아이 말 「옥상에서 뛰어내렸는데 무릎에서 피가 났어」 | 「마법 구름 옥상」으로 바꿈 | 진짜 옥상을 그대로 씀 |
| 한 편 시간 · 비용 | 약 45초 · $0.12 | 약 5초 · $0.008 |

- 시간 줄이기 시험(10편): 대본과 장면 계획을 **한 번에** 받고 생각 정도(effort)를 medium 으로 하면 통과율은 같고(10/10) 40초 · $0.10.
- **결정 (10/27)**: 대본은 Claude Opus 5.5, 한 번에 · medium. 안정성이 우선이고 예산이 맞는다(아래 6절). 남은 일: 백엔드 반영, 40초 기다림을 화면에서 덮기.

## 3. 안전 — 검열과 안전 판정

**지금 서비스** (`backend story_writer.check_input`): OpenAI `omni-moderation-latest` 로 **아이 입력과 AI 가 쓴 글을 모두** 검사한다.
아이 입력이 걸리면 「이 이야기는 만들 수 없어요」 → 다시 고르기. AI 글이 걸리면 아이 탓이 아니므로 다시 쓰게 한다.

**문제와 시험** (`exp safety-filter/`, 10/12): 아이 문장 56개(상상 · 위험 · 위기 섞음)에 기대 처리를 정해 견줬다.

| 방법 | 기대와 같음 | 놓친 위기 (10개 중) | 상상을 막음 (27개 중) |
|---|---|---|---|
| 지금 서비스 (moderation 걸리면 막음) | 17/56 | **5** | **15** |
| gpt-4o-mini 판정 | 54/56 | 0 | 0 |
| gpt-5.4-mini 판정 | 52/56 | 0 | 0 |
| gpt-5.5 판정 | 55/56 | 0 | 0 |
| **Claude Opus 5.5 판정 (10/27)** | **56/56** | **0** | **0** |

- 지금 방식은 「괴물이 선생님을 잡아먹었어요」 같은 상상을 막고, 「옥상에서 뛰어내렸어요」 · 「모르는 아저씨 차를 따라 탔어요」는 통과시켰다.
- AI 판정은 처리를 다섯 가지로 나눈다: 그대로 · 묘사만 빼기 · 보호자 기록 · 판타지로 바꾸기 · 멈추고 보호자.
- 판정을 맞혀도 **다시 쓴 문장이 안전하지 않을 수 있어** 한 번 더 판정해야 한다 (Opus 가 다시 쓴 13문장 중 12개가 재판정 통과).
- Opus 5.5 는 대본과 같은 업체로 묶을 수 있는 후보다. 문장당 3.3초, 56문장 + 재판정에 $0.56.
- 한계: 문장을 시험한 사람이 지었고 56개는 적다. 서비스 전에는 아동 보호 전문가가 기대를 정한 수백 개가 필요하다. 아직 서비스에 넣지 않았다.

## 4. 음성 — 읽어주기(TTS)와 아이 말 받기(STT)

**읽어주기** (`backend app/services/tts.py`, `voices.py`, 10/8)
- 업체는 설정으로 고른다: OpenAI `gpt-4o-mini-tts`(목소리 nova, 속도 0.9, 「어린이에게 동화를 읽어주듯 또박또박 천천히」 지시) 또는 ElevenLabs.
- **ElevenLabs `eleven_v4`, 나레이터 Anna Kim** 으로 정함 — 한국어 낭독 목소리가 이것뿐이었고, `eleven_multilingual_v2` 와 샘플을 들어 보고 v4 를 골랐다.
- 두 판: **나레이션만** / **캐릭터 목소리**. 캐릭터 목소리 판은 `text-to-dialogue` 한 번으로 여러 목소리를 이어 읽는다.
  - 인물 종류 8가지(아이-여 · 아이-남 · 어른-여 · 어른-남 · 할머니 · 할아버지 · 작은 동물 · 큰 동물)마다 한국어 목소리 후보를 정해 두고, 대본의 인물에 나눠 준다. 주인공 성별은 그림으로 짐작하지 않고 어른이 고른다.
  - 대사 감정(기쁨 · 다정 · 신남 · 놀람 · 슬픔 · 속삭임)을 v4 감정 태그로 바꾼다. 아이 대상이라 화내기 · 소리치기는 두지 않았다.
- 8쪽 그림책은 쪽마다 음성 파일. **음성이 실패해도 이야기는 완성된다** (브라우저 읽기로 대신).
- 쓰는 양 (2026-10-29): Starter 월 40,000자, `eleven_v4` 1자 1크레딧 · `eleven_v4_turbo` 0.5. 카드 이야기 한 편은 긴 판 580~650자, 짧은 판 90~110자. 나레이션 판은 조합마다 한 번만 만들어 저장하고, 캐릭터 판은 (조합, 이름, 주인공 목소리)마다 한 번.
- **turbo 로 했을 때 필요한 크레딧 (2026-10-29 정리)** — `eleven_v4_turbo` 는 1자 0.5크레딧(모델 목록 API 의 `character_cost_multiplier`). 청취 비교에서 v4 와 별 차이 없음(사용자), 대화 읽기(`text-to-dialogue`)도 turbo 로 된다. Starter 는 월 40,000크레딧.

  | 무엇 | 글자 | v4 크레딧 | turbo 크레딧 | Starter 몇 달 (turbo) |
  |---|---|---|---|---|
  | 긴 나레이션 남은 456편 (56편은 v4 로 만들어 둠) | 266,271 | 266,271 | 133,136 | 3.3 |
  | 짧은 나레이션 512편 | 45,299 | 45,299 | 22,650 | 0.6 |
  | **나레이션 판 다 채우기 (미리 만들 수 있는 전부)** | 311,570 | 311,570 | **155,786** | **3.9** |
  | 긴 캐릭터 판 한 편 (조합 · 이름 · 주인공 목소리마다) | 650 | 650 | 325 | — |
  | 짧은 캐릭터 판 한 편 | 110 | 110 | 55 | — |
  | 캐릭터 판 다 채우기 (이름 6 × 목소리 2 = 12벌) | 4,672,392 | 4,672,392 | 2,336,196 | 58 — 하지 않는다 |

  한 달 40,000크레딧으로 처음 요청 때 만드는 양(turbo): 긴 나레이션 약 137편 · 긴 캐릭터 약 123편 · 짧은 판 약 730~900편. 이미 만든 조합은 0. 카드 밖 이야기(말로 덧붙임 · 더 고른 칸)는 매번 새로 만든다.
  계정 조회의 사용량은 수십 분 늦게 따라온다 — 남은 양은 직접 센 글자로 판단한다.
- 잰 것: v4 는 속도(speed) 값을 무시한다. OpenAI 와 ElevenLabs 청취 비교는 남아 있다.

**아이 말 받기**
- 브라우저 내장 음성 인식(Web Speech API) — 유료 API 를 부르지 않는다.
- 아이 목소리가 브라우저 업체 서버로 가므로 **로그인한 보호자가 켜야만** 보인다(기본 꺼짐). 녹음은 저장하지 않는다. 인식한 글은 바로 쓰지 않고 「이걸로 할래요」로 확정해야 들어간다.

## 5. 이미지 — 계획

**배경 그림 실시간 생성 (계획, 10/27)**
- 쪽마다 Claude 가 쓴 영어 배경 지시문으로 GPT Image 가 배경(다른 인물 포함)을 그리고, 아이 그림 주인공은 그 위에 겹친다. 쪽 그림은 동시에 만든다.
- Gemini 이미지 API 는 약관이 18세 미만 대상 서비스를 금지해서 뺐다. 아직 가격 확인 · 시험 전.

## 6. 비용 · 정책

- **예산**: Claude API 매달 $100(Max 계정 지원) → 글은 Claude. OpenAI 는 전체 $80대 한 번 → 그림 생성에 아낀다.
- 편당 예상: 대본 + 장면 계획 Claude 약 $0.10 → 한 달 약 1,000편.
- 지금까지 시험에 쓴 돈: Claude 약 $7.0 (모델 비교 · 시간 시험 · 안전 판정), OpenAI 약 $0.25(비교 시험, 검열은 무료) + 10/12 시험들.
- 유료 호출은 모델 · 횟수 · 예상 금액을 먼저 말하고 허락받는다. 작은 모델로 먼저 보고, 같은 시험을 되풀이하지 않는다.
- **아동 대상 정책**: Anthropic 은 안전장치(검열 · AI 사용 알림 · 아동 개인정보 법 지키기)를 두면 미성년 대상 제품을 허용한다. Gemini API 추가 약관은 18세 미만 서비스를 금지한다. API 키는 서버 환경변수에만 둔다(프론트 · 문서 · 커밋에 두지 않음).

## 7. 확인이 더 필요한 것

- 아이콘 · 삽화를 어떻게 만들었는지 — `docs/image-prompts.md` 는 ChatGPT 웹에서 손으로 뽑는 프롬프트 54개 문서다. 실제 아이콘이 이 방식으로 나왔는지 만든 사람에게 확인.
- 비용 숫자는 공식 가격표 기준이 아니라 응답의 토큰 수 × 그날 확인한 단가로 계산했다.
- 모델 비교는 한 입력에 한 번씩, 30편 · 10편 규모다. 큰 경향은 믿을 만하지만 1~2편 차이는 우연일 수 있다.
