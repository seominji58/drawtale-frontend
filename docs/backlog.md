# 프론트엔드 남은 작업

기준일 2026-09-28. 골격 코드는 화면설계서 v0.2의 **S-01~S-16 + E-01 전부가
목 엔진으로 끝까지 도는 상태**다. 화면을 새로 만드는 일은 남아 있지 않다.

8주 일정에서 프론트 몫은 이랬다.

| 주차 | 프론트 할 일 | 현재 |
|---|---|---|
| 2~3주차 | 와이어프레임 및 아동 친화 화면 UI/UX 설계 | **끝** |
| 4~5주차 | Story Steps 화면 및 Canvas 애니메이션 구현 | **끝** (S-07, `CharacterCanvas`) |
| 6주차 | 순서 맞추기·지원 Level 구현, 애니메이션 장면 연결, 서버 통신 및 인증 연동 | 앞 세 개는 끝. **서버 연동이 남음** |
| 7주차 | 통합 테스트, 다양한 그림 테스트, 성능·지연 측정, 오류 케이스 개선 | 남음 |
| 8주차 | 발표자료·시연 영상 | 남음 |

목 엔진으로 S-01 → S-02 → S-03(샘플 그림) → S-04 → S-05 → S-07 → S-08 → S-09까지
실제로 돌려서 확인했다 (2026-09-28). `npm run typecheck` 통과.

### 2026-09-28에 고친 것

**S-04와 S-08이 개발 모드에서 영구히 멈추는 버그.** `useRef(new AbortController())`로
컨트롤러를 만들면 인스턴스가 하나뿐인데, `React.StrictMode`는 개발 모드에서 effect를
마운트 → 언마운트 → 재마운트로 두 번 돌린다. 첫 cleanup의 `ctrl.abort()`가 그 하나뿐인
컨트롤러를 끊어서, 두 번째 실행은 **이미 끊긴 signal**로 분석을 시작한다.
`mockAnalyze`가 첫 루프에서 `AbortError`를 던지고 `.catch`가 그걸 조용히 무시하므로
「친구를 만들고 있어요」에서 아무 일도 일어나지 않는다.

컨트롤러를 effect 안에서 만들도록 고쳤다 (`S04Analyzing.tsx`, `S08Generating.tsx`).
`stop()`은 `abort.current?.abort()`로 바뀌었다.

프로덕션 빌드에는 나타나지 않는 증상이라 `npm run build`로는 잡히지 않는다.
**앞으로 effect 안에서 쓰는 `AbortController`는 effect 안에서 만든다.**

**i — 개발 모드에서 같은 요청이 두 번 나간다.** 스텁 로그 실측:

```text

POST /api/stories {...} → s-000317cd   (2회, 이야기 두 편이 만들어졌다)
GET  /api/steps kind=place level=1     (2회)
```

`React.StrictMode`가 effect를 두 번 돌리는데, cleanup의 `ctrl.abort()`는 **이미
서버에 도착한 요청을 되돌리지 못한다.** 프로덕션 빌드에는 없는 일이지만, 개발과
7주차 통합 테스트 내내 **GPU 분석·OpenAI·TTS 비용이 두 배로 나간다.**
백엔드에 멱등키를 두거나, 통합 테스트 때만 StrictMode를 끄는 선택지가 있다.

**j — 작은 그림은 원본 그대로 간다.** `src/lib.ts` 21행이
`if (ratio === 1 && file.size < 2_000_000) return file;` 로 빠져나간다.

긴 변 1600px 이하이고 2MB 미만이면 원본 바이트가 그대로 올라간다.
스텁이 `⚠ image/png — 계약은 JPEG`를 찍어서 드러났다.
**백엔드는 PNG·WebP·HEIC까지 디코딩할 수 있어야 한다.** 계약 문장을 코드에 맞추거나
코드를 계약에 맞춘다.

**b 는 1·2번과 같은 뿌리다.** `CharacterCanvas` 가 쓰는 `imageUrl` 은
`URL.createObjectURL(file)` — 아이가 고른 **원본**이다 (`src/store/session.ts` 44행).
서버가 통일안대로 crop 기준 좌표를 보내면 캐릭터가 통째로 어긋난다.
계약에 `croppedImageUrl` 같은 필드를 두고 프론트가 그것을 쓰게 할지,
서버가 원본 기준으로 변환해 보낼지 **1·2번과 한자리에서 같이 정한다.**

**1·2번은 프론트가 혼자 고칠 일이 아니라 백엔드·AI와 합의할 항목이다.** 합의 결과에 따라
프론트가 손댈 것이 없을 수도 있다. 코드를 고치기 전에 이야기를 먼저 한다.

### 1. `head` 관절을 누가 만들지 백엔드와 합의하기

**프론트 작업이 아니라 합의 항목이다.** Meta 모델은 `head`를 내지 않는데
`skeleton.ts`는 그 점으로 머리를 그린다. 근거와 두 안은 `docs/open-decisions.md` 1번.

- 합의되면 **프론트는 손댈 것이 없다.** `api-contract.md`에 「`head`는 서버가 합성한
  파생 관절」이라고 한 줄 적는 것으로 끝난다
- 백엔드가 못 해 주면 프론트에서 파생 계산한다
  - `src/types/character.ts`의 `Keypoints`를 15개로 줄인다
  - `skeleton.ts`의 `toPixels()`에서 `head`를 계산해 `Pose`에 채운다

  - `BONES`의 `["neck", "head", ...]`와 `boneScale()`의 `rest.head.y`는 **그대로 둔다**
  - 설계서 S-06-01의 「관절점 16개」를 15개로 고친다
  - S-06에서 어른이 머리를 직접 못 끌게 되므로 UX 담당자와 확인할 것

### 2. 좌표 기준을 계약에 명시하기

## P1 — 서버 연동 (6주차)

### 4. `maskUrl` 반영 — 배경이 제거된 캐릭터로 렌더

지금 `maskUrl`은 타입에만 있고 아무 데서도 쓰이지 않는다. `CharacterCanvas`는
원본 그림을 그대로 잘라 쓰므로 **종이 배경이 조각마다 같이 따라온다.**

- `CharacterCanvas`에 `maskUrl?: string | null` prop을 받는다
- 마스크가 있으면 오프스크린 캔버스에서 `globalCompositeOperation = "destination-in"`으로
  배경을 지운 이미지를 한 번 만들어 두고, 뼈 조각은 그 결과에서 잘라낸다
- **`null`이면 원본으로 렌더하고 그대로 진행한다** (설계서 S-05-02가 요구하는 동작이다).
  마스크가 없다고 오류를 내지 않는다
- 서버는 `rembg`로 마스크를 만든다 (remove.bg 아님)

### 5. 실서버 연동 검증

**팀원 서버를 기다릴 필요가 없다.** `tools/stub-server/` 를 띄우면 아래 전부를
지금 확인할 수 있다. 조작판(`http://localhost:8000/`)에서 시나리오를 바꾼다.

- `.env`의 `VITE_ENGINE`을 `agent` 또는 `finetuned`로 바꿔 전 구간을 돌린다
- SSE 재연결(3초 간격 두 번), 30초 타임아웃, `ENGINE_TIMEOUT` → E-01 경로를 실제로 끊어서 확인
  - 조작판의 「SSE 끊기」·「TIMEOUT(30초)」. **재연결은 지금 구현돼 있지 않다** (P0-0 e)
- 음성만 실패한 경우(`audioUrl: null`) S-09가 낭독 버튼만 비활성으로 두고
  **진행은 계속하는지** 확인 — 부분 실패를 전체 실패로 처리하지 않아야 한다
  - 조작판의 「음성 null / wav」로 양쪽 다 본다
- 오류 코드 6종이 E-01에서 맞는 문장으로 갈라지는지 (조작판의 「분석 실패 주입」)
- 신뢰도 0.55로 두고 S-05에 「어른에게 도움 받기」가 뜨는지
- Level 1·2·3에서 `GET /api/steps`가 2·4·6개로 오는지
- 비회원 토큰으로도 API가 통하는지 확인 (체험 2편) — **지금은 토큰을 아예 안 싣는다** (P0-0 f)

### 10.5 Level 1 선택지 카드 아래쪽이 빈다

**1024×768에서 확인했다 (2026-09-28).** 카드 크기 자체는 문제가 아니었다 —
데스크톱 와이드에서만 과하게 커 보였고, 태블릿 기준 해상도에서는 적당하다.

남은 것은 **카드 안 여백 분포**다. `.choice::before`가 `inset: 0 0 40% 0`이라
상단 60%가 milk, 하단 40%가 흰색인데, Level 2·3은 아이콘 아래 라벨이 그 흰 영역을
채우는 반면 **Level 1은 라벨이 없어 하단 40%가 통째로 빈다.**

손볼 곳은 `::before`의 비율이다. Level 1 에서만 `inset: 0 0 25% 0` 정도로 줄이면
흰 영역이 좁아지고 아이콘이 카드 중심에 가까워진다. `--choice-align`과 같은 방식으로
CSS 변수를 하나 더 두면 된다.

급한 일은 아니다. 실제 아이콘 그림(`docs/art-direction.md`)이 들어오면 인상이
달라지므로 그때 다시 보고 정하는 편이 낫다.

### 11. S-10 드래그 앤 드롭 추가

지금은 **탭 두 번**만 된다. 이건 의도된 기본 조작이다 — 드래그만 지원하면
소근육 조작이 어려운 아이가 배제된다. **드래그는 추가 수단으로만 붙인다.**

### 13. 조각 이음매 품질

`walk` 모션에서 어깨 회전이 ±0.44 rad까지 가서 **팔 조각이 몸통 위에 겹쳐 보인다.**
샘플 그림으로 S-09를 재생하면 바로 보인다. 머리도 목에서 살짝 떠 보인다.

통합 정리 문서가 브라우저 렌더의 약점으로 짚은 「관절마다 잘라 돌려 이음매가 보일 수

- 그리는 순서 — `BONES`는 뒤에서 앞으로 그린다. 팔이 몸통 뒤로 가야 하는 모션에서는
  순서를 바꿔야 할 수 있다

**서버 렌더로 결정되면 S-09에서는 이 문제가 없어진다** (메시를 부드럽게 휘므로).
그래도 S-05·S-06은 브라우저 렌더를 유지하니 여기서는 남는다.
`docs/open-decisions.md` 5번 결정을 기다렸다가 손대는 편이 낫다.
